# The oldest Home Assistant hacs.json claims to support, so that the claim is
# tested rather than asserted. Nothing else exercises it: a contributor's venv
# and the main CI job both run the pin in requirements_test.txt, and a release
# that quietly needed something newer would only surface as a bug report from
# whoever runs the old version. tests/test_floor.py is what makes this job say
# something: it imports every module and names the APIs the floor has to have.
#
# 2025.4.0, and it was found by running the suite rather than by reading a
# changelog. Config subentries -- one entry per account, one subentry per
# device, the shape this integration is built on -- are absent from 2025.2.0:
# `ConfigSubentryFlow` does not import, and test_floor.py says so. The whole
# 2025.3.x line, which does have them, cannot be installed at all: it pins
# `aiohttp==3.11.13`, which PyPI has since yanked for a regression, so pip
# cannot resolve it. 2025.4.0 is the oldest release that installs and passes,
# and a floor nobody can install is a claim nobody can test.
#
# It needs Python >= 3.13.0, which is what the matrix pairs it with. Raising
# the floor here means raising it in hacs.json too; test_floor.py fails if the
# two drift.
homeassistant==2025.4.0
pytest==9.1.1
